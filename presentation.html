Executive Summary & Operational Reality

The Freight Mileage Dilemma in India

1. Rural Dropouts
Cellular coverage drops across ghat sections, transport nagars, and remote national highways. Cloud-dependent systems stop logging, resulting in unbilled kilometers.
2. Sensor Noise
Flyovers and massive metallic container bodies cause satellite multipath reflections, creating 2 km teleports in 5 seconds and inflating distances by 15% to 40%.
3. Rigid Baselines
Fixed corridor tables (e.g. Chennai-Bangalore = 350 km) ignore outer ring bypasses, loading hub detours, and diversions, sparking driver-operator friction.
4. Prohibitive Costs
AIS-140 hardware and commercial routing APIs (Google Maps) impose heavy recurring monthly fees that squeeze thin freight margins.
THE NAMMA LORRY SOLUTION: 100% Offline Tracking + Mathematical Guard at ₹0 Cost
Combines commodity Android phone GNSS sensors, client-side anomaly filtering, local offline queuing, and multi-model arbitration across OpenStreetMap/OSRM and Supabase.

System Architecture & Pipeline

End-to-End Telemetry Pipeline

1. GNSS Satellites Fix
Hardware GPS streams raw coordinates (Lat, Lng, Accuracy, Speed, Heading, Timestamp) without requiring mobile data.
2. 3-Stage Quality Guard
Client-side mathematical filtering eliminates accuracy errors > 50m, speeds > 120 km/h, and 3-point multipath detour spikes.
3. Offline Storage Queue
Points are stamped with sync_status: pending and queued in LocalStorage / IndexedDB during network blackouts.
4. Supabase Cloud Sync
Upon reconnection, pending batches sync to Supabase with idempotent upserts, guaranteeing zero duplicate entries.
5. Multi-Model Distance
Evaluates Model A (Baseline/1.25x), Model B (Filtered GPS Haversine), and Model C (OSRM Road Network).
6. Cockpit & Fleet Map
Real-time driver HUD, animated lorry markers, trip audit breakdown, daily stats, and admin fleet surveillance.

Telemetry Ingestion

Hardware GPS Acquisition & Calibration

1. HTML5 Geolocation Watcher
Connects directly to device GNSS chipsets via navigator.geolocation.watchPosition() with enableHighAccuracy: true, maximumAge: 2000ms, and timeout: 12000ms.
2. Pre-Trip GNSS Locking
Detects starting coordinates before the lorry rolls. Drivers can click "Lock / Re-acquire Start GPS" to pin warehouse loading bay positions, eliminating false starts.
3. Reverse Geocode Resolution
Latitude/longitude coordinates are resolved against OpenStreetMap Nominatim into recognizable hub landmarks (e.g. "Sriperumbudur Industrial Corridor").
4. Real-Time Telemetry Stream
Every reading extracts Latitude, Longitude, Accuracy (m), Speed (m/s converted to km/h via * 3.6), Heading (0°-360°), and hardware UTC timestamps.

Signal Processing & Anomaly Detection

3-Stage GPS Quality Guard Engine

Check 1: Accuracy Filter
accuracy ≤ 50.0 meters
Cell-tower triangulation generates 300m - 1500m error margins. Any point with error > 50m is flagged POOR_ACCURACY and purged.
Check 2: Speed Jump Filter
v = (Δd / Δt) * 3.6 ≤ 120 km/h
Computes instantaneous speed between consecutive valid points. Rejects any leap exceeding realistic heavy lorry highway limits (> 120 km/h).
Check 3: 3-Point Spike Filter
Detour > 2.2x & Δd > 400m
Evaluates sliding triplets (P_i-1 → P_i → P_i+1). Drops transient satellite multipath reflections under highway flyovers.
Battery Optimization & Adaptive Sampling (Section 10)
Dynamic interval switching: 30s when stationary (< 5 km/h) • 10s in city traffic (5-50 km/h) • 5s at highway cruising speed (> 50 km/h). Conserves smartphone battery over 12-hour hauls.

Distance Calculation

Multi-Model Distance Engine (A / B / C)

MODEL A: Known Baseline
Corridor Catalog:
• Chennai ↔ Bengaluru: 348.5 KM
• Chennai ↔ Sriperumbudur: 42.0 KM
• Chennai ↔ Vellore: 138.0 KM

Road Factor Fallback:
Multiplies straight-line displacement by 1.25x winding factor.

Emergency fallback only.
MODEL B: Filtered Haversine
100% Offline Geodesic:
Accumulates spherical distance between consecutive cleaned GPS coordinates:
d = Σ Haversine(P_i, P_i+1)
Earth radius R = 6,371 km.

Reflects actual route taken, bypasses, and loading bay diversions.
MODEL C: OSM / OSRM
Road Snapped Distance:
Queries OpenStreetMap OSRM routing engine with true start and stop coordinates.

Direct Start-to-End road routing prevents intermediate waypoint U-turn anomalies across divided highways and medians.

Audit & Reconciliation

Algorithmic Arbiter & Decision Matrix

1. Stationary Vehicle Lock (0.0 KM)
If origin and stop coordinates have displacement < 60m and total distance < 80m, the trip locks to 0.0 KM. Prevents billing for stationary depot idling.
2. Physical Boundary Verification
Both Model B (GPS) and Model C (OSRM) must be ≥ 0.85 * straight-line displacement. A road trajectory cannot physically be shorter than a straight line.
3. Outlier Detour Rejection
If OSRM generates extreme detours (Model C > 2.8 * displacement), it is rejected as a highway median turnaround artifact in favor of verified driver GPS trajectory.
4. Model Selection Hierarchy
• Both Agree (≤ 35% diff) → Model B (Road Confirmed)
• GPS Truncated → Model C (OSRM Road Network)
• OSRM Offline → Model B (GPS Filtered)
• Both Inconclusive → Model A (Fallback) or NEEDS_REVIEW

Resilience & Reliability

Offline-First Resilience & Zero-Duplicate Sync

Offline Point Capture
When cellular network drops (isOnline = false), GPS tracking continues uninterrupted. Points are tagged with sync_status: 'pending' and appended to local storage.
Realtime Network Listener
Listens for browser online and offline events. Includes a manual simulation toggle in the header for QA verification and driver demonstration.
Atomic Batch Upload
When connection is restored, pending points are uploaded in atomic batches of 50. Mutex promise locking prevents concurrent sync race conditions.
Idempotent Upsert Deduplication
Supabase receives points via upsert with onConflict: 'id', ignoreDuplicates: true. Guarantees 0 duplicate records in the cloud database.
